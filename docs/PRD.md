# GiftPortals product brief

Some gifts fit in your hand. Others take you to an entire world.

GiftPortals turns a souvenir, its original photo, a place and a personal story into an explorable digital memory. The traveler keeps the physical object while a recipient can receive its digital box immediately. The product connects three experiences: an immersive postcard, a discovery map and a contemplative memory train.

## People and core journey

1. A traveler signs in, uploads a souvenir photo and optional place photos/audio, writes a story and explicitly chooses what location may be shared.
2. After AI consent, the cloud schedules bounded object and environment jobs independently. Originals remain available if either job fails.
3. The traveler reviews the memory and creates a revocable link. Copying a link is described as sharing a link, not as sending an email.
4. An anonymous recipient opens only that gift. Signing in and claiming it adds the memory to their collection without marking its location as a physical visit.
5. The map distinguishes physical visits, discoveries through memories and wishes. A memory train crosses authorized memory fragments, each returning to its source.

## Pilot and scope

The pilot is São Paulo with a Santos connection and a received Paris memory. Demo people, dates, travels and stories are fictional. Perdizes is visited in the demo; Jabaquara remains unvisited. Paulista is a corridor/point of interest rather than an administrative district. The hierarchy is world → country → state → municipality → district or explicitly named region → point.

Deliver an English, mobile-first HTTPS app, persistent cloud collections, a real Tripo image-to-3D demonstration, a real World Labs artistic environment, three demo memories, two fictional users and 6–10 sourced points. Browser fallback must retain photo/story when WebGL, audio or permissions are unavailable.

## Acceptance and evidence

Production must work anonymously for public demo/gift reads and persist signed-in collections across devices. Unauthorized collection reads, gift revocation and claimed recipient access require tests. A received memory must not create a physical visit; parent visit aggregation must be recomputed after edits/deletion. The 8–12 second train must support skip, replay, mute and reduced motion. Cloud jobs must retain provider IDs and resume independently of an open browser. No frontend bundle may include privileged credentials. Submission needs a usable build, a 1–2 minute recorded walkthrough and at least three actual high-resolution screenshots/GIFs.

## Evidence boundaries

Generated geometry and environments are artistic interpretations, never verified reconstruction or proof of a visit. Precomputed demo content is labeled. GPS/metadata is optional and consent based. An API balance or successful local test does not establish cloud operation or submission. Only a production readback establishes deployment; only the portal receipt establishes submission.
